Lab 6.1 OSCAL Artifacts
This directory contains the OSCAL artifacts created for Lab 6.1 and documents how implementation evidence maps to security control requirements.

Artifact Overview
Component Definition
File: compliant-s3.json

Describes the Terraform module:

terraform/primitives/compliant-s3
The module implements a compliant-by-default AWS S3 storage configuration including:

Server-side encryption (AES-256)
Bucket versioning
Public access blocking
Access logging
Required compliance tagging
The component definition maps these implementation details to applicable NIST SP 800-53 Rev. 5 controls.

Profile
File: cge-p-minimum.json

Defines the minimum set of security controls inherited or satisfied by the component.

Control Mapping
The component provides evidence supporting controls such as:

Control	Description
AC-3	Access Enforcement
AU-3	Content of Audit Records
CM-6	Configuration Settings
SC-28	Protection of Information at Rest
Evidence Location
Evidence associated with the component is stored in the evidence vault and referenced through OSCAL evidence links similar to:

s3://EVIDENCE_VAULT/runs/LATEST/evidence-LATEST.tar.gz
The evidence package contains artifacts generated by the compliance pipeline, including:

Terraform plans
Validation results
Configuration outputs
Supporting audit evidence
Validation
OSCAL artifacts were validated using:

trestle validate
Validation output is stored in:

evidence/lab-6-1/trestle-validate.txt
Traceability
The assessment chain for this component is:

Profile
  ↓
Selected Controls
  ↓
Component Definition
  ↓
Implemented Requirements
  ↓
Evidence Link
  ↓
Signed Evidence Bundle
This traceability allows an assessor to follow a security control claim from the profile through the implementation and directly to supporting evidence.

UUID Requirements
All OSCAL objects requiring identifiers use valid UUID Version 4 values generated with:

python3 -c "import uuid; print(uuid.uuid4())"
Placeholders such as:

GENERATED-UUID-V4
PARTY-UUID-V4
COMPONENT-UUID-V4
CI-UUID-V4
REQ-UUID-V4
PROFILE-UUID-V4
must be replaced with unique generated UUIDv4 values before validation.
